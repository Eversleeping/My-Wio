# 操作中心

## 独立应用服务器凭据

服务器「修改凭据」提供 Codex API、Git、Gemini API、Claude API 四个页签。Codex 和 Git 可分别应用；Git 支持多选，全部取消会删除 Wio 托管的 Git 凭据与提交身份配置。单独修改 Git 不读取或更改 Codex 配置，也不重启 Codex；单独修改 Codex 不更改 Git 文件和预设绑定。

独立应用要求执行端 Agent 为 0.3.02 或更高版本，旧 Agent 会提示升级。控制端仍兼容原有不带 `scope` 的组合凭据接口；新界面使用 `scope: "codex"` 或 `scope: "git"`。同一服务器的 Git、Codex 和旧组合凭据操作互斥，只有 Agent 成功回执后才更新对应预设绑定。

## 操作中断

操作中心显示 Agent 操作的排队、执行和完成状态。Git 检查、仓库扫描、工作区文件扫描、变更扫描、文件预览和差异预览支持点击「中断」。执行端需更新至 0.2.96 或更高版本；旧版本按钮会提示升级。

点击后显示「中断中」，目标操作仍保留原状态。Agent 取消对应执行上下文并等待任务退出后，控制端才根据真实回执更新为已取消；若任务恰好已完成，则保留原来的完成结果。停止超过 15 秒仍未得到确认时，中断请求失败，目标记录保持执行中，可再次点击重试。

Agent 离线时中断请求排队，重新连接后优先处理。重复点击会复用尚未完成的中断请求。执行中因 Agent 重启而丢失回执的中断请求会自动重送，并一并恢复目标操作的回执。尚未执行或当前 Agent 已无对应执行实例的遗留操作，会保存取消回执，阻止迟到命令在重连或重启后重新执行；记录结果会注明当前 Agent 没有活跃执行实例。该确认范围是 Agent 管理的操作，不包括之前进程遗留的独立子进程。

中断扫描或预览后，对应的加载状态会释放，可重新刷新。旧操作的中断不会覆盖较新请求的快照。任务会话、部署、升级、凭据变更和文件写入继续使用各自的控制流程。

## 页面刷新与扫描性能

控制端的 PostgreSQL 连接统一设置 `jit=off`。页面接口以短查询为主；关联表较小、统计信息尚未更新时，查询成本估算可能触发 JIT 编译，编译本身比实际查询慢数秒。该设置随每个连接建立生效，无需修改 PostgreSQL 全局配置或其他应用的连接。

前端收到实时事件时，会先完成正在进行的请求，再合并补取最新数据，避免慢网络下不断取消请求、一直显示加载中。离开页面或切换资源仍会取消旧请求。文件变更扫描与 Git 检查在等待结果时每 2 秒补查一次，完成或离开变更面板后停止，作为实时通知的兜底。

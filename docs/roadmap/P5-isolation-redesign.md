# P5-04 凭据与进程边界重设计验证

2026-11-16，前置原型的产品基线为 `e392caa` / Agent 0.3.30，完整结果记录于 `29de234`。前置矩阵已经通过，当前在 `main` 工作区接入产品并验收；待提交的实现为 Agent 0.3.31、schema 6。P5-04 与 P5-05 均保持进行中，界面与文档已准备，临时内核的通过结果不代替实际服务器验收。

## 候选方案

采用三种互补的边界，不再只依赖文件打开限制：

1. 可信 Agent 持有上游认证。每个 CLI 进程只得到独立的临时会话凭据，访问一个固定上游、固定用途的回环代理。停止进程时撤销凭据和正在进行的请求。
2. bubblewrap 建立用户、挂载、PID、IPC 和 UTS 命名空间。只绑定该工作区、所属主仓库的 Git 元数据、必要的原生状态及专用临时目录；系统和安装目录只读。隐藏 Agent 状态中的凭据、其他工作区和特权 pathname socket。只读挂载同时防止权限和时间戳改动。
3. 在沙箱内应用 Landlock ABI 9 的 pathname UNIX socket 限制，以及 abstract socket 和 signal scopes，补足保留宿主网络时的 IPC 边界。文件规则继续限制 CLI 和所有工具进程，不能解除已继承的规则；此前 ABI 6 的候选范围已按工作区别名反例收紧。

此前仅检查原路径时，候选组合使用 ABI 6；追加工作区别名检查后，该判断已被反例推翻，产品必须要求 ABI 9，见后文修订。纯 Landlock 候选仍有 P5-03 记录的 pathname socket 和元数据缺口，不能与组合结果混为一谈。

网络出口继续按已确认边界保留，Agent 的 MCP、提问和流式服务通过回环访问。上游代理不能成为任意 HTTP 转发器，也不能把临时凭据升级为账户管理或其他项目的权限。原生登录的认证和刷新须由可信端处理；向 CLI 提供原生认证文件的副本不满足这一要求。

## 代理验证

全部上游、认证、账户和工作区资源均为合成数据；使用官方 CLI 和当前 Wio 适配器，没有调用账户模型。

| 检查项 | 当前证据 |
| --- | --- |
| 上游认证只在可信端使用 | 三引擎 API 预设及服务环境探测通过；CLI、版本查询和模型工具只检查环境变量名及是否含合成上游值 |
| 会话之间不能借用认证 | 独立令牌交叉调用被拒绝；没有进程隔离时，同账号进程仍能从其他 CLI 的环境借走其临时凭据，已复现，组合模式必须阻止这种读取 |
| 固定目标和有限路由 | 外来 Host、绝对地址、非规范路径、认证查询、转发头和管理路由不能改变目标；重定向不进入另一服务 |

| 流式回显 | 明文、JSON 转义、URL 编码及常用 Base64 表示的合成认证过滤通过；分片边界、gzip 及不支持的多重编码处理经过攻击性检查 |

| Codex、Claude 原生登录 | 合成原生登录状态、图片和真实模型工具往返通过；Codex 的预热帧与推理帧分别处理，首次工具缺失来自本地模型夹具，不修改 CLI 或产品 |
| Gemini 原生登录 | 官方 GCA 环境入口、合成原生登录、图片和工具往返通过；可信项目、model/cachedContent 资源和字段别名绑定通过攻击性检查。OAuth cache-only 会访问硬编码 tokeninfo，不能把随机 lease 填入缓存就声称支持 |

固定路由不能替代原生账户或项目绑定。Google 原型先复现六种请求 JSON 的项目越界，再收紧项目、资源和字段别名并完成 race 复验；普通消息中的 JSON 文本保持原文。改动已合入主原型并再次通过范围检查和真实支持内核的原生往返；该问题只存在于临时原型，没有进入产品。

## 支持内核的进程验证

通过临时启动的 Linux 6.12 内核执行真实系统调用和 bubblewrap，不模拟 Landlock 或 namespace 成功。仅挂载事先准备的公开运行库及 CLI 安装文件，没有连接宿主磁盘、账户服务或特权 socket。

非特权 Agent 和从 root 降到非特权账号的启动器分别验证。当前已通过工作区读写执行、外部凭据和其他工作区不可读、外部写入和元数据改动失败、两个特权 pathname socket 及 abstract socket 不可连接、控制面合成初始环境不可读、无有效 capabilities、`no_new_privs` 和回环访问。跨域信号被拒绝，独立接收进程没有收到信号。

禁止嵌套用户命名空间的正向对照通过：相同账号在沙箱外可以创建，在沙箱内被拒绝。使用单线程外部命令比较两条路径；Go 运行时已有线程的 `unshare` 错误不作为安全边界的证据。Linux 的限额拒绝可返回 `ENOSPC`，不能只用 `EPERM` 作为拒绝成立的唯一证据。最终两种形态的完整边界命令退出 0，耗时 8.431 秒。

三种官方 CLI 在组合模式下的 MCP 往返已通过，合成成果通过 Agent 回环从另一工作区返回。三引擎 API 预设/服务环境的图片、工具环境和 Codex/Claude 原生登录完整组合矩阵退出 0，耗时 245.651 秒。Gemini GCA 原生登录另外在相同组合边界通过图片、模型工具和父刷新凭据不可读检查。恢复、编辑、分叉、worktree 提交、中断及真正的跨工作区子 CLI 协作已经补验，结果见下一节；单轮 MCP 成果返回仍不能代替这些检查。

Gemini 的 GCA 入口仍尝试硬编码 userinfo，临时离线内核拒绝该连接后非致命继续；不将这条结果算成真实 Google 账户验证。原生认证刷新、ADC、Vertex、service-account 和工作负载身份尚未验证；接入时必须由可信端处理，或明确拒绝对应认证方式，不能把原始凭据直接传给 CLI。CLI 的非推理实验查询被有限路由拒绝，首轮推理仍通过。

临时运行库最初缺少脚本使用的公开解释器，虚拟 CPU 也不满足其中一个 CLI 的指令要求；补齐公开运行库和虚拟 CPU 后复验。只读公开文件的缓存设置消除了冷启动超时，现有适配器的启动期限没有放宽。失败和正向结果均保留，不把环境准备失败列为产品缺陷。

## 完整原生流程与子 CLI 协作

2026-11-16 接续时，独立测试先在本机通过，再放入相同的真实支持内核组合复验。每个引擎均验证重新启动后的恢复、同工作区分叉、目标 worktree 分叉并实际提交、编辑保留与删除的上下文，以及中断取消上游请求。分叉和编辑同时检查源原生历史摘要不变；Claude、Gemini 另外检查逐轮启动器已经退出。

Claude 完整组合流程通过，耗时 79.92 秒；Gemini 通过，耗时 288.50 秒。两者的跨工作区真实子 CLI 协作分别通过，耗时 34.20 和 91.49 秒。来源 CLI 经 Wio MCP 创建目标会话；可信回调启动目标工作区的官方 CLI，其模型工具实际写入并提交合成成果，随后经 MCP 返回，来源 CLI 对目标文件的直接读取同时被拒绝。

Codex 首轮组合验证的临时模型只等待工具一秒，收到异步回执后重复发起了命令，导致合成提交断言失败。修正夹具为等待并轮询同一个工具会话后，仅补验 Codex：完整流程通过，耗时 52.90 秒；跨工作区子 CLI 协作通过，耗时 28.89 秒。最终补验命令退出 0，耗时 89.236 秒。没有修改产品或官方 CLI 的超时。首次公开测试二进制只有属主执行权限的启动失败也保留在本地记录中。

至此，前置原型矩阵已补齐，可以开始产品接入。上述结果仍使用临时启动器及合成认证；产品实现须重新核验，实际服务器和账户的验收仍未执行。

## 产品接入前必须落实的规则

- 在启动 Codex app-server 之前确定工作区；既有进程不能通过后续请求扩展允许目录。跨工作区分叉使用目标范围的新进程。共享查询只能得到明确的查询范围。
- 原生配置和历史保留所需读写权限，但上游认证文件必须隐藏或用临时认证覆盖。不能放行整个 HOME 或整个 Agent 状态目录；工作区和 CLI 安装目录位于状态目录内时，只绑定需要的子树。
- 只传递明确允许的描述符，CLI 获得的 API 描述符只能含临时凭据。临时输入、历史 loader 和分叉快照必须位于允许的专用范围内，启动失败也释放父进程副本。
- 环境认证、原生登录和自定义模型接口分别解析。无法安全代理的认证或资源引用明确拒绝，不把未实现的模式直接传给 CLI。
- 配置默认关闭。开启但缺少内核能力、可用 bubblewrap、命名空间或完整规则时明确拒绝；不退回部分文件限制。免密 sudo 与该模式互斥。
- root 内置 Agent 必须真实降权、清除附加组和有效 capabilities 后再建立边界。临时内核的 root 启动器结果不能代替控制面容器的运行验收。

## 接续发现的支持条件修订（2026-11-17）

原会话另一组真实内核检查复现了 ABI 6 的外部 pathname socket 工作区别名可连接；前文 ABI 6 的通过矩阵未覆盖该项，不能据此认定完整边界。产品支持条件改为 ABI 9，处理 `LANDLOCK_ACCESS_FS_RESOLVE_UNIX` 且不授予任何路径该权限，结合既有命名空间、只读挂载、abstract socket 和信号 scopes。补充别名拒绝和隔离域内部 socket 可用的产品回归，低 ABI 须明确拒绝。

产品回归先在真实 ABI 6 内核复现两个外部 socket 别名可连接，再在临时真实 ABI 9 内核验证拒绝；没有模拟系统调用成功。普通用户和 root 降权两种形态的边界、挂载路径替换防护及凭据生命周期全部通过，整体命令退出 0（45.4 秒）。

产品管理器下的三种官方 CLI 完整流程补验通过：Codex 76.98 秒、Claude 170.58 秒、Gemini 340.58 秒，涵盖恢复、编辑、分叉、worktree 提交和中断。Claude 原有 Bun 崩溃已通过支持原子替换私有账户配置的目录挂载解决；失败记录仍保留。该组合命令随后在子 CLI 协作期间触发测试包总计 11 分钟看门狗，命令本身退出 1；单独运行协作组全部通过（Codex 35.63 秒、Claude 44.89 秒、Gemini 106.00 秒），没有修改产品启动超时。

真实 API、gRPC、Agent 和合成引擎的开启隔离跨进程组，普通用户及 root 降权形态均通过（17.71 秒、16.35 秒，整个临时内核命令退出 0）。首次 root Gemini 失败来自可信设置初始化创建了 root 专属父目录，已在写设置前创建缺失目录并分配隔离账号；已有管理员目录的属主与权限不变。合成外部写入探针也已去掉创建标志，避免在私有临时目录创建同名影子文件而误判成宿主写入成功。

## 未完成的验收

公开运行库与临时内核的验证不等于目标服务器已支持。实际外部 Agent、root 控制面容器、真实账户认证及完整隔离会话尚未验收；本轮没有推送、发布、部署、修改宿主安全策略或连接真实特权服务。

产品工作区已接入独立的 `sandbox`、`credentialproxy` 和 `sessionisolation` 包、三引擎启动与短进程、默认关闭配置、实际状态心跳、扩展迁移及注册/修复选项。挂载源由可信父进程以描述符固定，避免启动时的路径替换扩大范围；跨工作区分叉启动目标范围的新进程。不能安全代理的云认证及到期的原生登录明确拒绝；原生认证刷新仍由可信端进行。

三引擎产品完整流程、两种形态的开启隔离跨进程链路及跨工作区子 CLI 协作的本地结果见上一节。通用 Go 检查、PostgreSQL、前端 518 项单元测试、类型检查与桌面/移动 E2E（47 通过、11 既有跳过）已通过；完整验收及失败复验记录见 [P5 执行记录](P5-execution-isolation.md#执行记录)。全部日志和临时运行库只保存在会话本地目录。

上述本地验收和阶段文件要求的真实服务器完整流程全部满足后，才可将 P5-04 标记为已完成。本轮已有授权不包含推送或部署。

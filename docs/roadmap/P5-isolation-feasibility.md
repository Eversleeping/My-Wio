# P5-03 隔离可行性验证

返回 [P5 执行隔离](P5-execution-isolation.md#可行性验证结果)和[路线图总览](README.md)。

2026-11-16，基线 `bdad111` / Agent 0.3.29。用户已确认原威胁边界和 Landlock 优先的验证顺序；**下面是实验结论，具体技术选型仍待用户确认**。

当前验证环境中，两种候选都没有满足完整边界。Landlock 能限制文件访问，但合成 Docker socket、安装助手 socket 和跨域信号仍可用；临时 bubblewrap 无法建立用户命名空间。Codex/Gemini 自身的托管密钥仍出现在工具环境中，文件规则没有消除这条泄露路径。建议重新设计 P5-04 的前置验证，保留已完成的 P5-02，不将这次原型接入产品作为隔离模式。

## 实验范围

- 最小 Landlock 包装器先应用路径规则，再执行真实 CLI。规则允许工作区、共享 Git 元数据、原生状态和本次实验的专用临时树；系统与 CLI 安装文件只读、可执行，不放行整个 HOME、`/etc` 或 `/proc`。
- 合成资源包括 Agent 令牌、三引擎配置/密钥、Git 凭据、控制面密钥、另一个工作区、工作区之外的可写文件、两个 pathname UNIX socket、一个 abstract UNIX socket及一个同账号的测试进程。没有连接真实 Docker/安装助手或读取真实凭据。
- 三个官方 CLI 分别为 Codex 0.169.0、Claude Code 2.1.323、Gemini 0.68.0，通过当前 Wio 适配器运行。HOME、模型接口、认证和仓库均为临时或合成资源，不调用账户模型。CLI 的 `no_new_privs` 已在包装器中核对。
- 基础检查既由包装器里的进程执行，也由三个原生模型工具执行。只保存变量名、访问是否成功和用例结果；凭据文件摘要与工作区之外文件保持不变。原型、overlay、具体工具路径、内核能力与日志在会话本地备忘中，不进入仓库。
- CLI 功能实验允许该引擎的临时测试树，以便同一用例跨轮次恢复。它验证兼容性，不充当多个并发会话临时目录互相隔离的验收。

最小包装器的文件读取结果不能掩盖 socket 失败：Docker 这类提供主机级操作的服务可以绕过文件限制，安装助手虽只接受固定动作，也仍违反本阶段要求的连接边界。三个原生 CLI 工具均复现了合成 socket 的可连接性，已经足以否定当前规则作为完整隔离边界。

Gemini 历史恢复失败与 P5-01 的无隔离原生探测一致，报 `Gemini CLI cannot synchronize restored history`；独立续聊和编辑用例都在第二轮恢复处失败，未改产品兼容适配器。Codex 图片用例对模型请求内容作断言，Landlock 和保持相同目录/模型设置的无隔离对照都没有收到图片项；重启恢复、分叉、编辑和技能的独立结果仍然成立，图片保持未验收。两项限制已登记到总览“发现的问题”。

## Landlock 的要求与限制

能力必须通过 `landlock_create_ruleset(..., LANDLOCK_CREATE_RULESET_VERSION)` 查询，不能只比较发行版或内核版本。以下是通用主线版本范围，来自 [Linux man-pages](https://man7.org/linux/man-pages/man7/landlock.7.html)和[内核 Landlock 文档](https://docs.kernel.org/userspace-api/landlock.html)；发行版回移植可能改变对应关系。

| 能力 | 最低 ABI | 主线范围及意义 |
| --- | --- | --- |
| 基础文件访问 | 1 | Linux 5.13 引入；单有它不足以限制所有写入 |
| 跨目录 rename/link | 2 | Linux 5.19；worktree/Git 流程需要核对 `REFER` |
| 文件截断 | 3 | Linux 6.2；低于此能力不能宣称工作区之外不可写 |
| TCP bind/connect | 4 | Linux 6.7；不是 UNIX socket 限制。本阶段保留网络出口，不启用 TCP 限制 |
| 字符/块设备 ioctl | 5 | Linux 6.10；只给确实需要的设备权限，不放行全部 `/dev` |
| abstract UNIX socket 与跨域信号 | 6 | Linux 6.12；通过 `scoped` 限制，不能保护 pathname Docker socket |
| pathname UNIX socket 查找/连接 | 9 | Linux 7.1；需处理 `LANDLOCK_ACCESS_FS_RESOLVE_UNIX`。本轮没有在具备此能力的环境实测，不据文档宣称产品已经支持 |

还须编译启用 `CONFIG_SECURITY_LANDLOCK`，并在启动时启用该 LSM。单纯允许读取 socket 文件、禁止写文件或拥有 TCP 规则，都不能代替 pathname socket 的连接限制。

常见发行版的 GA 基线如 Ubuntu 22.04 的 5.15、Ubuntu 24.04 的 6.8、Debian 12 的 6.1、Debian 13 的 6.12，均不能仅凭该基线声称拥有 ABI 9。HWE、更新内核或回移植另行查询实际能力；本轮没有逐台探测目标服务器。发行版范围参见 [Ubuntu 内核发布周期](https://ubuntu.com/about/release-cycle#ubuntu-kernel-release-cycle)、[Debian 12 发布说明](https://www.debian.org/releases/bookworm/amd64/release-notes/ch-whats-new.en.html)和[Debian 13 发布说明](https://www.debian.org/releases/trixie/release-notes/whats-new.en.html)。

`no_new_privs` 是包装器应用规则的必要条件，阻止后续通过 setuid 等取得新特权，因此不能保留模型免密 sudo 的工作流。它不会自动清除启动前已有的 root 权限和 capabilities。本轮是非 root 原型，没有验收真实 root 控制面容器；内置控制机不能据此标记支持，需要单独验证降权、capabilities、挂载和凭据边界。

## bubblewrap 备选结果

Landlock socket 检查失败后，按已确认顺序验证了临时解包的 bubblewrap 0.9.0。最小命名空间启动在 uid map 初始化时报 `Permission denied`，在执行目标命令前退出。因此其文件规则、三个 CLI、回环服务与 root 容器均没有运行结果，不能写成“通过”。没有安装宿主机软件包、修改 AppArmor/用户命名空间策略或使用 sudo。

这个结果只说明当前临时非特权入口不可用。系统安装路径的安全策略、打包方式、用户命名空间设置和容器的 seccomp/capabilities 都可能不同，需要在拟支持的部署形态里实际验证；不把临时包的失败推广为所有 bubblewrap 安装均不可用。参考 [bubblewrap 项目说明](https://github.com/containers/bubblewrap)。

若保留宿主网络以访问 Agent 回环服务，还要独立验证 abstract UNIX socket 的边界；仅隐藏两个 pathname socket 不代表所有 IPC 已隔离。若创建网络命名空间，必须重新验证模型接口、MCP、提问和流式代理，不能假设原回环地址继续可用。

## 进程与凭据设计结论

P2-09 已让 Codex 每个会话持有独立 app-server，本轮证明在启动前确定工作区和临时树后，其原生恢复、分叉和编辑可运行。原产品仍在进程启动后才给线程传 `cwd`；隔离接入要将规则输入前移，不能先启动一个没有工作区范围的进程再补权限。跨工作区分叉应由目标工作区的新进程执行，旧进程不能扩展范围。共享的模型/技能查询进程也须有明确的查询范围，不能为省事放行所有工作区。

CLI 自带的线程沙箱、权限/审批模式只能作为补充：本轮 Codex 使用当前 Wio 的 `danger-full-access` 设置，Claude/Gemini 使用各自的原生权限模式。外层文件规则对 CLI 和工具都生效；这些选项不会补上当前 socket 或自身环境密钥的缺口。

三个尚未验证的前置要先解决：

1. **上游凭据不交给不可信进程树。** 评估由 Agent 持有上游密钥的模型接口代理，CLI/工具只接触会话限权凭据；验证代理不能被改成向任意地址转发上游认证，并覆盖服务环境认证和原生登录状态。当前只是重设计方向，不是已有产品能力。
2. **文件、IPC 与进程边界同时成立。** Landlock 路径选型至少重新验证 ABI 9 和 `scoped`；bubblewrap 路径需重新验证用户/挂载/PID/网络规则。已继承的描述符、SSH agent、特权 socket、CLI 状态中的认证也要纳入规则，不将“文件不可读”泛化为“凭据不可取得”。
3. **在真实目标环境完成完整矩阵。** 外部默认 Agent 与 root 内置控制机分别验收，免密 sudo 明确不支持；补齐未通过的原生图片/历史流程和跨工作区协作。CI 中不支持内核的跳过只能证明拒绝路径，不能代替支持路径验收。

工作区、原生状态和主仓库 Git 元数据的允许范围都可包含模型已获准读取的内容；共享 Git 对象是 worktree 提交的必要输入，不承诺同一仓库的历史对象互相不可见。已确认的同引擎原生历史共享继续保留。真实部署、上游账户认证、支持 ABI 9 的环境以及有效的 bubblewrap 环境均未验收。

## 待确认的 D4 结论

建议保留 P5-02 的默认环境收紧，重新设计 P5-04 并先补验证上述三个前置。任何候选在目标环境里无法完整应用规则时都明确拒绝隔离会话，不回退到文件规则部分生效的模式。P5-04 和 P5-05 保持待开始；P5-03 等待用户确认这份技术结论。

用户也可选择暂缓可选隔离，将 P5-04 / P5-05 取消并保留现有默认收紧。当前记录没有替用户选择取消，也没有把 P5-03 标记已完成。
